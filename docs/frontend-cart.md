# Корзина покупателя (frontend)

## Состояние и сохранение

Корзина доступна без авторизации на `/cart`. CartProvider использует React Context и hooks. Позиция определяется **offerId**, поэтому предложения разных продавцов одной игры не объединяются.

В localStorage, ключ `eneba:cart`, сохраняется только массив `{ offerId, quantity }`. Названия, продавцы, изображения, цены, остатки и ID игр не сохраняются. Повторное добавление увеличивает количество, счётчик Header показывает сумму количеств. Минимум — 1, максимум ограничен известным остатком из API. При обновлённых данных из API сохранённое завышенное количество уменьшается до доступного.

Невалидный JSON/устаревший корневой формат дают пустую корзину. Невалидные строки пропускаются; лишние поля, включая подставные цены, удаляются. Дубли offerId объединяются с максимальным корректным quantity, без суммирования повреждённых дублей. localStorage синхронизируется между вкладками; обработчик игнорирует sessionStorage и учитывает известные ограничения остатков. При запрете записи корзина работает в памяти, а страница предупреждает об отсутствии сохранения. Один effect сообщает результат внешней записи в storage; для него точечно пояснено исключение lint-правила set-state-in-effect.

## API и ограничение текущего backend

Переиспользуются getGames и getGame, без изменений API-клиента или Laravel. Данные доступного предложения (seller, price, quantity) берутся из свежего GET страницы игры. Цены из браузерного хранилища не используются. Суммы вычисляются в целых центах через BigInt, без ошибок десятичного сложения.

После просмотра игры в памяти остаются только подсказки offerId → gameId и известные ограничения количества. При открытии корзины известные игры повторно запрашиваются для актуализации цен и остатков. Подсказки не являются кешем цен и исчезают после перезагрузки.

**В API нет получения предложения по offerId или пакетной загрузки предложений корзины.** Поэтому после холодного восстановления frontend просматривает алфавитные страницы каталога и загружает детали подходящих игр, до нахождения всех сохранённых offerId. Игры с offers_count=0 пропускаются, запросы деталей выполняются группами максимум по 4. При нынешних 40 играх полный холодный обход может потребовать 44 GET-запроса; при наличии подсказок обычно достаточно GET для каждой известной игры. Это fallback в рамках ограничения «только frontend», а не рекомендуемый API для большого каталога.

Для дальнейшего масштабирования нужен согласованный batch lookup предложений по offerId с игрой, продавцом, ценой и доступностью. Сейчас API скрывает неактивные/исчерпанные предложения, поэтому для недоступной позиции невозможно восстановить прежние название/продавца/картинку по одному offerId. Она честно показывается как недоступный Offer #ID, без придуманной цены, с возможностью удаления. Полностью успешный обход отличает недоступность от сетевой ошибки. При ошибке корзина сохраняется, есть Try again. Старый API без списка offers и невалидные ответы обрабатываются контролируемо.

## Интерфейс

- Add to cart на существующих предложениях страницы игры, подтверждение добавления и блокировка по известному остатку.
- Активная ссылка корзины и счётчик в Header.
- Адаптивная страница: обложка/существующая заглушка, игра, продавец, цена единицы, количество ±, стоимость позиции, Remove, итоговая сумма, Continue shopping.
- Refresh prices повторяет чтение текущих API-данных.
- Пустая корзина предлагает вернуться к каталогу. Недоступные позиции не включаются в сумму и блокируют продолжение до удаления.
- Proceed to checkout только показывает сообщение о необходимости авторизации. Заказы, оплата и резервирование не выполняются.

Добавление в корзину не меняет offers.quantity и не резервирует ключи. Итоговая серверная проверка цен/остатков относится к будущему checkout.

## Проверки

```powershell
docker compose exec -T frontend node --test tests/cart.test.mjs tests/cart-api.test.mjs tests/games.test.mjs
docker compose exec -T frontend npm run lint
docker compose exec -T frontend npm run build
```

Автотесты: **124 passed** (107 существующих API-тестов и 17 новых тестов корзины/загрузчика). TypeScript, Oxlint (0 warnings/errors), production build прошли. Сборка проверялась во временной копии без публикации.

Chromium на настоящем `http://localhost:5173`, без подмены данных в основном сценарии: пустая корзина, добавление/повтор, два продавца одной игры, счётчик, лимиты min/stock, точные суммы, удаление, reload, закрытие и повторный запуск браузера с тем же профилем. Также проверены подставная цена в localStorage против реальной API-цены, завышенное сохранённое количество, повреждённый JSON, реально отсутствующий offerId и синхронизация вкладок.

API-ошибка/повтор, невалидный JSON цены, задержанный запрос с удалением позиции и заблокированная запись storage проверены отдельными браузерными сценариями. Нет необработанных JS-ошибок. Checkout не отправляет запросы. Ширины 320/375/768/1024/1440 — без горизонтального скролла.

Backend, миграции, API и зависимости не изменены. Контрольный дамп данных games/game_popularities/sellers/offers/digital_keys до и после совпал. Deploy, commit и push не выполнялись.
